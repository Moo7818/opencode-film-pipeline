## 二、融入定位

### 当前流程

```
episode_storyboard_script（阶段10）:
  1. 读剧本 + 读设定
  2. LLM 直接创作分镜 JSON（场→组→镜）
  3. 写 分镜脚本.json
  4. 机械拆分 → 分组/组{N}.json
```

### 融入后流程

```
episode_storyboard_script（阶段10）:
  Phase A：分镜稿创作（storytelling pipeline，精简版）
    A1. 读剧本 + 读所有设定产物 → 戏剧结构笔记
        ├─ 分集剧本（画面内容 + 口播文案）
        ├─ 全局设定.md
        ├─ 角色设定/
        ├─ 场景设定/
        └─ 道具设定/
    A2. 场次戏剧地图（sequence map）
    A3. 逐场戏核 + shot flow
    A4. 粗略缩略图任务（rough thumbnails）
    A5. 台词时长校验（Agent 自主计算，无需脚本）
    → 产出：分镜稿_临时.md（Markdown 格式，过程产物）

  Phase B：分镜脚本 JSON 生成（原有逻辑）
    B1. 读分镜稿（分镜稿_临时.md）
        ← Phase A 已完成剧本理解和设定读取，
          Phase B 不再重复读取剧本和设定
    B2. LLM 基于分镜稿创作分镜 JSON（场→组→镜）
    B3. 写 分镜脚本.json
    B4. 机械拆分 → 分组/组{N}.json
```

> **数据流原则**：Phase A 负责所有信息采集（剧本 + 设定），Phase B 仅消费 Phase A 的产出（分镜稿_临时.md）。这避免了重复读取带来的 token 浪费和潜在的上下文不一致。

### 不拆分为独立阶段的原因

分镜稿是分镜脚本的**创作前置**，不是独立交付物。拆为独立阶段会导致：
- 阶段链从 17 增至 18，影响全链路
- 分镜稿是过程产物，下游不直接消费
- 分镜稿和分镜脚本的创作者相同（storyboard-director），无需跨 agent 交接

## 三、storytelling pipeline 的精简策略

源 skill 的 15 步管线面向**电影级完整分镜包**，对短视频（15-30 秒/集）过重。需精简为 5 步：

| 源 15 步 | 精简后 | 保留/裁剪理由 |
|----------|--------|-------------|
| Step 1: 通读剧本 | A1 保留 | 戏剧结构理解是基础；A1 同时读取所有设定产物（全局设定/角色/场景/道具），Phase B 无需重复读取 |
| Step 2: 场次戏剧地图 | A2 保留 | 场次切分是分镜脚本的场级依据 |
| Step 3: 逐场镜头策略 | A3 合并 | 合入 A3 的 shot flow |
| Step 4: 场戏核 + shot flow | A3 保留 | shot flow 是组/镜级的关键输入 |
| Step 5: 粗略缩略图 pass 1 | A4 保留 | 缩略图任务表是镜头分解的直接依据 |
| Step 5.5: 台词时长校验 | A5 保留 | Agent 自主判断情绪并计算台词时长，无需脚本 |
| Step 6-9: 动画预览/结构修正/语言精修/缩略图 pass 2 | **裁剪** | 短视频无需多轮 rough/clean 迭代 |
| Step 10-11: 关键帧/粗动画 | **裁剪** | 短视频镜头数少，无需关键帧筛选 |
| Step 12-15: 逐镜稿/总稿/clean pass/交付 | **裁剪** | 分镜脚本 JSON 已是最终交付物 |

### 精简后的产出

```
{剧集号}/分镜/
├── 分镜稿_临时.md              ← Phase A 产出（过程产物）
│   ├── 戏剧结构笔记
│   ├── 场次戏剧地图
│   ├── 逐场戏核 + shot flow
│   └── 粗略缩略图任务表
├── 分镜脚本.json                ← Phase B 产出（正式交付物）
└── 分组/
    ├── 组1.json
    └── ...
```

### 改动 7：移除 dialogue_timing_gate.py，Agent 自主计算台词时长

**设计决策**：情绪判断和台词时长计算本质上是语义理解任务，应由 LLM 完成，不应交给脚本的字符串匹配。脚本关键词匹配无法覆盖自然语言的多样表达（如"强忍泪水""咬牙切齿""一字一顿"等），匹配失败时回退为正常语速会导致时长估算严重失准。

**改动内容**：
- 删除 `scripts/dialogue_timing_gate.py`
- 台词时长校验改为 Agent 在 A4 步骤中自主完成，直接写入分镜稿面板
- Agent 需遵守以下计算规则：

**情绪语速模型**（基础语速 4.0 chars/s × 情绪系数）：

| 情绪 | 系数 | 实际语速 | 典型场景 |
|------|------|---------|---------|
| 悲恸 | 0.50x | 2.0 chars/s | 哽咽/啜泣/泣不成声 |
| 犹豫 | 0.60x | 2.4 chars/s | 结巴/迟疑/支吾 |
| 沉重 | 0.75x | 3.0 chars/s | 颤抖/压抑/悲愤 |
| 低语 | 0.85x | 3.4 chars/s | 轻声/耳语/呢喃 |
| 正常 | 1.00x | 4.0 chars/s | 对白/旁白叙述 |
| 急促 | 1.15x | 4.6 chars/s | 紧张/慌张/匆忙 |
| 激昂 | 1.25x | 5.0 chars/s | 高声/洪亮/坚定 |
| 爆发 | 1.30x | 5.2 chars/s | 呐喊/咆哮/怒吼 |

**计算公式**：
- 总需时 = 朗读时间 + 标点停顿 + 情绪停顿
- 朗读时间 = 中文字数 ÷ 情绪语速
- 标点停顿：逗号 0.3s / 句号·感叹号·问号 0.5s / 省略号 0.8s / 破折号 0.5s
- 情绪停顿：悲恸每分句 +0.5s / 犹豫 +0.4s / 沉重 +0.3s / 低语 +0.2s / 爆发 +0.1s

**校验原则**：台词需时 ≤ 面板 hold（严格容纳，无溢出容忍）

**修复优先级**：1.压缩台词 → 2.调整情绪 → 3.延长 hold → 4.拆分面板

## 六、风险与注意事项

1. **token 消耗增加**：Phase A 的分镜稿创作是额外 LLM 工作，单集 token 消耗预计增加 30-50%。可通过精简模板和压缩输出来缓解。
2. **分镜稿质量依赖**：Phase B 的分镜 JSON 质量直接受 Phase A 分镜稿质量影响。如果分镜稿的 shot flow 设计不佳，分镜 JSON 也会受影响。需在 SKILL.md 中强调 Phase A 的质量检查点。
3. **短视频适配度**：源 skill 面向电影/预告片，精简后需确认 5 步管线对 15-30 秒短视频是否足够轻量。如果仍然过重，可进一步压缩为 3 步（通读剧本→场次地图+shot flow→缩略图任务）。
4. **Agent 时长计算准确性**：Agent 自主计算台词时长依赖 LLM 的数学推理能力，可能存在计算偏差。通过在 SKILL.md 中提供明确的计算公式和情绪语速表来约束。
5. **AGENTS.md 规则**：`.opencode/` 下文件修改应由 system-engineer 子 agent 执行。本计划供 system-engineer 作为执行依据。
