# 角色资产改造计划：妆造衣橱模型

> 状态：规划中
> 创建时间：2026-07-12
> 涉及 skill：`roles-ref-generator`、`producer`、`storyboard-generator`、`video-director-libtv`
> 关联规则：`.opencode/rules/pipeline.md`、`.opencode/rules/orchestrator.md`

## 背景与问题

### 当前架构

```
Tier 1 选角资产（白T恤，七视图）
  ↓ 参考图
Tier 3 剧集级参考（每集独立生成，七视图）
```

### 核心问题

1. **缺少定妆层**：选角资产穿白T恤，无法直接用于剧集；剧集级参考每集独立生成常规妆造，导致同一角色的日常外观在不同剧集中漂移不一致
2. **版本化定妆方案的缺陷**：按时间线划分定妆版本（v1/v2/v3），无法解决跨剧集复用——多剧集使用类似妆造却重复生成，且角色服装过于多变分散观众注意力
3. **冗余开销**：没有复用机制，每集需要变化时都重新生成完整资产

## 改造方案：妆造衣橱模型

### 核心思路

角色拥有一组**有限命名的妆造**，每套妆造只生成一次，所有剧集/场景从衣橱中引用。妆造按"名称"组织（如：默认/战斗/礼服），而非按时间线版本组织。

### 三层资产架构

| 层级 | 定义 | 服装来源 | 参考图来源 | 生成时机 | 数量 |
|------|------|---------|-----------|---------|------|
| Tier 1 选角资产 | 角色身份本体（面部/体型/表情） | 固定白色短袖T恤 | 人物采样图 | Phase 2，一次 | 每角色 1 个 |
| Tier 2 定妆资产 | 角色在某剧情中的常规妆造 | 从角色设定「造型设计」提取 | Tier 1 选角资产 | Phase 2 + 剧情需要时 | 每角色 N 个（按妆造名） |
| Tier 3 剧集/场级参考 | 对当前定妆的临时偏离 | 从分镜脚本提取 | Tier 2 当前定妆资产 | Phase 3，变化检测时 | 按需 |

### 妆造分类

| 妆造类型 | 说明 | 示例 |
|---------|------|------|
| 默认妆造 | 角色最常见的日常外观 | 校服/便装 |
| 命名妆造 | 剧情需要的特定装扮 | 战斗铠甲/礼服/夜行衣 |
| 状态妆造 | 身体状态变化 | 受伤/生病/变身 |

### 妆造周期 vs 妆造衣橱

| 维度 | 版本化定妆（已否决） | 妆造衣橱（采纳） |
|------|---------------------|-----------------|
| 组织方式 | 按时间线（v1/v2/v3） | 按妆造名（默认/战斗/礼服） |
| 剧集引用 | 引用"当前版本" | 引用"该场景对应的妆造名" |
| 复用性 | 同版本内复用，跨版本不复用 | 任何剧集只要穿同一套妆造就复用 |
| 冗余 | 时间线切换 = 新生成 | 妆造已存在 = 直接引用 |
| 数量控制 | 随剧情转折线性增长 | 有限集合，由创作层面有意控制 |

## 角色设定文件调整：造型设计字段

### 设计决策

将原 Producer 角色设定模板中的「服装特征」字段升级为「造型设计」，统合服装与妆容，按妆造名分组。

### 模板结构

```markdown
## 造型设计
### 默认
白衬衫+格子裙，清透裸妆，自然眉形，淡粉色唇彩
### 战斗铠甲
银色板甲，红色披风，战场粗眉，无妆容
### 礼服
深蓝色晚礼服，精致盘发，红唇妆容
```

### roles-ref-generator 参数映射

| 参数 | 含义 | 取值来源 |
|------|------|---------|
| string3 | 头饰（简述） | 造型设计（当前妆造名下提取） |
| string4 | 妆容（简述） | 造型设计（当前妆造名下提取） |
| string5 | 服装（简述） | 造型设计（当前妆造名下提取） |
| string9 | 头饰详述 | 造型设计扩展 |
| string10 | 服装详述 | 造型设计扩展 |

Agent 从「造型设计」同一章节的不同妆造名下提取信息，负责拆分出头饰、妆容、服装三类。

## 变化判定阈值

### 判定原则

**只认"换了一套衣服"，不认"同一套衣服的不同状态"**。

触发新妆造的条件是——该差异会导致角色在生图中呈现明显不同的视觉身份。如果观众一眼能看出"这是另一套造型"，则触发；如果观众觉得"还是那套衣服只是姿态不同"，则不触发。

### 判定标准

| 差异类型 | 是否触发新妆造 | 示例 |
|---------|--------------|------|
| **整体服装品类变化** | ✅ 触发 | 便装→铠甲、常服→礼服 |
| **核心配饰增减** | ✅ 触发 | 佩戴/摘除面具、披风、头盔 |
| **发型/头饰整体变化** | ✅ 触发 | 散发→束发、戴冠/摘冠 |
| **颜色变化** | ⚠️ 视情况 | 同款换色不触发，主色调明显不同则触发 |
| **局部破损/污渍** | ❌ 不触发 | 衣角磨损、袖口脏污 |
| **细微动作导致的形变** | ❌ 不触发 | 衣摆飘起、袖子卷起 |
| **配饰微调** | ❌ 不触发 | 腰带位置变化、领口开合 |
| **光影/氛围差异** | ❌ 不触发 | 暖光下的衣服vs冷光下的衣服 |

### 数量控制

- 每个角色建议妆造数 ≤ 5 套（含默认）
- 超过 5 套时，orchestrator 应介入审查——是否可以通过合并相似妆造或调整分镜描述来控制数量
- 这个上限不是硬编码禁止，而是触发 orchestrator 的审查提醒

### episode 模式工作流

1. 读取分镜脚本中的妆造名（标注格式）
2. 查衣橱——已存在 → 引用
3. 不存在 → 判定差异类型
   - 符合触发标准 → 报告新妆造需求给 orchestrator
   - 不符合 → 归入最接近的已有妆造，不报告

## 妆造衣橱索引文件

### 文件路径

`project/{项目名}/全局依赖/角色设定/妆造衣橱.md`

### 职责

记录每个角色的所有妆造清单，是 orchestrator 编排和 episode 模式引用的单一事实来源。

### 结构

```markdown
# 妆造衣橱

## 角色A

| 妆造名 | 造型描述 | 参考图文件 | 生成状态 | 首次使用 |
|--------|---------|-----------|---------|---------|
| 默认 | 校服，白衬衫+格子裙，清透裸妆 | {角色名}_默认.png | ✅ 已生成 | — |
| 战斗铠甲 | 银色板甲，红色披风，战场粗眉 | {角色名}_战斗铠甲.png | ✅ 已生成 | 第3集 |
| 礼服 | 深蓝色晚礼服，精致盘发，红唇妆容 | {角色名}_礼服.png | ⏳ 待生成 | 第7集 |

## 角色B

| 妆造名 | 造型描述 | 参考图文件 | 生成状态 | 首次使用 |
|--------|---------|-----------|---------|---------|
| 默认 | 黑色风衣，高领毛衣，无妆容 | {角色名}_默认.png | ✅ 已生成 | — |
```

### 字段说明

| 字段 | 说明 |
|------|------|
| 妆造名 | 妆造的唯一标识，用于分镜脚本中引用 |
| 造型描述 | 服装、配饰、妆容、发型的简要描述（对应角色设定「造型设计」中的妆造名条目） |
| 参考图文件 | 对应的 Tier 2 资产文件名 |
| 生成状态 | ✅ 已生成 / ⏳ 待生成 |
| 首次使用 | 该妆造首次出现的剧集号（默认妆造为 — ） |

## 各角色与衣橱的关系

| 角色 | 与衣橱的关系 |
|------|-------------|
| orchestrator | 维护衣橱：新妆造需求写入衣橱标记"待生成"；生成完成后更新为"已生成"；超过 5 套时审查 |
| global 模式 | 生成选角资产 + 默认妆造，写入衣橱（初始化） |
| episode 模式 | **只读**衣橱：按分镜脚本中的妆造名查衣橱，已生成的直接引用，不生成 |
| Art-director | 读取衣橱中"待生成"的条目执行生图 |

## 资产命名约定

```
全局依赖/角色设定/角色参考图/
├── {角色名}_选角.png          ← Tier 1 选角资产
├── {角色名}_默认.png          ← Tier 2 默认妆造
├── {角色名}_战斗铠甲.png      ← Tier 2 命名妆造
├── {角色名}_礼服.png          ← Tier 2 命名妆造
└── {角色名}_受伤.png          ← Tier 2 状态妆造
```

剧集级不再产出独立的角色参考图，而是引用衣橱中对应的妆造资产。真正需要生成的只有衣橱中的新妆造。

## 工作流变化

### Phase 2（全局视觉资产生成）

1. 生成 Tier 1 选角资产（白T恤，七视图）
2. 生成 Tier 2 默认妆造（角色设定「造型设计」中的默认妆造，七视图，参考 Tier 1）
3. 初始化妆造衣橱索引文件

### Phase 3（剧集级）

1. 读取分镜脚本，识别每场戏角色的妆造名
2. 查询衣橱：该妆造名是否已存在？
   - **已存在** → 不生成，直接引用该衣橱资产
   - **不存在** → 判定差异类型（见变化判定阈值）
     - 符合触发标准 → 向 orchestrator 报告"发现新妆造需求"
     - 不符合 → 归入最接近的已有妆造，不报告
3. orchestrator 决定是否加入衣橱并触发 global 模式生成新妆造
4. 新妆造生成完成后加入衣橱，供后续剧集复用

### Phase 3.5（资产同步，新增）

5. 由 coordinator 将当前剧集所需的妆造资产从 `全局依赖/角色设定/角色参考图/` 复制到 `temp/分组素材/{剧集号}/角色参考/`，供 video-director 使用

## 换装类型判定

| 换装类型 | 属于哪层 | 示例 |
|---------|---------|------|
| 剧情转折导致的常规换装 | Tier 2 新妆造（加入衣橱） | 时间跳跃后改穿便装、身份转变后换制服 |
| 特定场景的临时换装 | Tier 3 剧集级 | 战斗穿铠甲、宴会穿礼服 |
| 身体状态变化 | Tier 3 剧集级 | 受伤绷带、生病虚弱 |
| 回忆/闪回 | Tier 3 剧集级（引用旧妆造） | 成年角色回忆少年时期 |

## 上下游适配分析

### P0 — 阻断性问题

#### 1. Producer 缺「视觉参考风格」字段

**问题**：roles-ref-generator 的 `common.md` 依赖角色设定中的「视觉参考风格」字段判断 string1（质感类型）。Producer 输出模板中不存在此字段，Agent 只能靠猜测兜底。

**适配方案**：在 Producer 的 `rules/output_format.md` 角色设定模板中新增 `## 设计参考` 章节，包含 `视觉参考风格` 字段（如"3D卡通，皮克斯风格"）。

#### 2. Producer「服装特征」需升级为「造型设计」

**问题**：当前「服装特征」为自由文本，按场景散列。衣橱模型需要按妆造名组织，且需统合妆容。

**适配方案**：将「服装特征」升级为「造型设计」，按妆造名分组，每组包含服装+妆容+发型描述。

#### 3. 分镜脚本无「妆造名」标注

**问题**：衣橱模型的核心是 episode 模式按"妆造名"查衣橱。分镜脚本 JSON 的 17 个字段中无妆造名，且 validators.py 禁止 `人物`、`images` 等结构化字段。

**适配方案**：不修改分镜 JSON 结构，在分镜的 `场景描述` 或 `站位/调度` 字段中约定妆造名标注格式：`[妆造:战斗铠甲] 郑和立于旗舰船头`。episode 模式用正则提取。这不需要改 schema，只是创作约定。

#### 4. video-director 素材路径与衣橱资产路径不匹配

**问题**：video-director 从 `temp/分组素材/{剧集号}/角色参考/*.png` 读取角色参考图，但衣橱资产产出在 `全局依赖/角色设定/角色参考图/`。

**适配方案**：在 pipeline 规则中新增 Phase 3.5 步骤——Phase 5 完成后由 coordinator 将当前剧集所需的妆造资产从全局路径复制到 temp 目录。复制逻辑改为"按分镜中的妆造名匹配衣橱，复制对应资产"。

#### 5. episode 模式需改为只读衣橱

**问题**：当前 episode 模式变化检测后直接生成剧集专属参考图。衣橱模型要求 episode 只读衣橱，不自行生成。

**适配方案**：重写 `rules/episode.md` 步骤 3-4，改为妆造匹配逻辑。

### P1 — 增强性问题

#### 6. 妆造衣橱索引缺少 schema

**问题**：当前改造计划中衣橱是 Markdown 格式，没有结构化校验。

**适配方案**：补充 JSON 格式的衣橱索引文件（`妆造衣橱.json`），与 Markdown 版本同步维护。JSON 供 Agent 程序化读取，Markdown 供人类查阅。

### 不需要改动的部分

- **Art Director**：不感知衣橱模型，只消费任务 JSON，output_path + filename 机制不变
- **image-generation.json Schema**：不涉及妆造概念，无需修改
- **GRSAI MCP Server**：不关心角色资产组织方式，images 数组照常上传
- **分镜 validators.py**：不新增字段，妆造名以约定格式嵌入现有文本字段

| 维度 | 当前 | 需要调整 |

| episode 模式 | 参考图引用选角资产 | 改为引用当前定妆的 Tier 2 资产 |

| video-director | 素材路径硬编码 | 依赖 coordinator 同步，路径不变 |

## 关键约束

- 衣橱由 **orchestrator 维护**，skill 只读取——global 模式初始化时写入默认妆造，之后不在 skill 层面修改衣橱
- episode 模式遇到衣橱中不存在的妆造时，**不自行生成**，而是向 orchestrator 报告"发现新妆造需求"，由 orchestrator 决定是否加入衣橱并触发 global 模式生成
- 妆造数量受控——不会因为分镜脚本中的随意描述就无限增长，由变化判定阈值 + 数量上限（≤5套）双重控制
- 变化判定原则：**只认"换了一套衣服"，不认"同一套衣服的不同状态"**
