# 共享定义

三个定位模式（global / episode / group）共用以下规范。差异点在各自主文件中说明。

## 七视图硬约束

- 一个角色 = 一个 task。每个角色只生成 1 个 task，该 task 的 prompt 描述 **一张网格图内包含 7 个视图**（左半侧半身正面照 + 右上表情三连图 + 右下全身三视图）。
- **绝对禁止**为不同角度分别创建独立 task。
- **aspectRatio 必须固定为 16:9**（横向构图才能容纳七视图并列排版）。
- 此约束适用于 global 模式（Tier 1 选角 + Tier 2 定妆/新妆造）。episode 模式不再生成七视图，仅做妆造匹配（见 `rules/episode.md`）。群像使用群像模板。

## 缺省值原则（重要）

AI 图像模型对某些视觉属性有统计偏见——如果 prompt 不明确声明，模型会按训练数据"自动填空"（例如男性历史人物默认加胡须、古代人物默认苍老）。**必须对每个可能被默认填充的视觉特征做显式声明**：若不存在则明确否定，若存在则具体描述。

关键防范列表（必需在 prompt 中显式声明的属性）：

| 属性 | 风险 | 正确做法 |
|------|------|---------|
| 胡须 | 男性角色易被默认添加胡须 | 无胡须则写"无须"；有胡须则描述类型（山羊胡/络腮胡等） |
| 皱纹/年龄感 | 年龄未明确时模型默认偏大 | 按角色设定明确写"面容光滑无皱纹"或相应描述 |
| 发型 | 历史角色易被默认古装发型 | 显式描述发型，不依赖模型默认 |
| 体态 | 男性角色易被默认壮硕 | 按角色设定描述（清瘦/健壮/魁梧等）|
| 质感类型 | string1 易被默认使用"超写实真人摄影写真" | 必须根据角色视觉风格从「string1 质感类型选择表」中选择对应值 |
| 服装文字 | 模型可能自动在服装上生成文字/logo | 必须在 prompt 末尾显式写"服装上没有任何文字、logos、标签或文字标识，no text，no logo" |

## string1 质感类型选择表

`string1`（质感类型）**不能固定使用默认值**，必须根据角色设定的「视觉参考风格」字段判断视觉风格类型，从下表中选择对应的值：

| 视觉风格类型 | 判断依据（角色设定中的关键词） | string1 值 |
|-------------|-------------------------------|-----------|
| `photo_realistic` | 真人摄影、写真、真人实拍、照片级真实 | 超写实真人摄影写真 |
| `game_cg` | 游戏CG、游戏建模、CG建模、游戏角色渲染、次世代、3A级 | AAA级游戏CG角色渲染 |
| `cartoon_2d` | 2D动画、动漫、二次元、日漫、国漫、插画 | 动画电影级精绘插画 |
| `3d_cartoon` | 3D卡通、皮克斯、迪士尼、Pixar、Pixar/Disney-inspired、modern feature-animation、3D stylized character、三维动画、软萌3D | 3D卡通渲染 |
| `hand_drawn` | 手绘、水墨、工笔、素描、水彩 | 手绘艺术精描 |
| `gta_v` | GTA V、Rockstar、侠盗猎车手、洛圣都 | AAA级游戏CG角色渲染 |
| `ghibli` | 吉卜力、宫崎骏、龙猫、千与千寻 | 动画电影级精绘插画 |

**判断规则**：子 Agent 必须从角色设定文件的「视觉参考风格」或整体描述中提取关键词，匹配上表中最接近的视觉风格类型，选择对应的 string1 值。若无明确关键词匹配，默认为 `photo_realistic`。

## 风格参考按需注入规则

角色设定中的「视觉参考风格」字段可能指定具体动画/游戏风格。Agent 应按需判断：

### 判定逻辑

1. 从角色设定文件的「视觉参考风格」或整体描述中提取风格关键词
2. 匹配 `string1 质感类型选择表` 中的「判断依据」列
3. 若匹配成功 → 加载 skill 内置 `reference/{风格名}.md` 参考文件
4. 若角色设定未指定视觉参考风格 → 不加载，按默认 `photo_realistic` 逻辑填充

### 注入规则

加载参考文件后，按以下规则覆盖 Prompt 模板的对应参数：

| 参数 | 注入来源 | 说明 |
|------|---------|------|
| string1 | 参考文件 front-matter 的 `string1` 字段 | 覆盖质感类型选择表的默认值 |
| string2 | 参考文件 front-matter 的 `string2` 字段 | 覆盖美学风格 |
| string11 | 参考文件正文 `string11` 章节 | 覆盖背景+光影描述 |
| string12 | 参考文件正文 `string12` 章节 | 覆盖整体质感描述 |

### 项目级覆盖

若项目根目录存在 `卡通风格提示词模板.md`，**优先**从该文件匹配同名风格模板提取关键词，注入对应参数。该文件中的模板可完全替代 skill 内置 `reference/` 的同名风格。

### 执行流程

在构建 Prompt 时：

1. 读取角色设定，提取「视觉参考风格」
2. 若存在明确风格 → 查找 `reference/{风格名}.md`（或项目级风格模板）
3. 若找到参考文件 → 加载并提取 string1/string2/string8_style_injection/string11/string12 值
4. 若未找到（或无风格指定）→ 使用原有的默认生成逻辑

### 双语并列规则

关键风格描述必须使用 `{中文描述} {English keyword}` 双语格式，以中英文逗号 `，` 分隔不同词组。双语并列有助于模型同时理解语义和风格指向，提升生成一致性。

正确示例：
```
柔光全局照明 soft global illumination，电影级影棚布光 cinematic studio lighting
```

错误示例（仅中文）：
```
柔光全局照明，电影级影棚布光
```

### string8 风格化造型注入规则

在角色特征描述（string8）末尾，追加风格化造型说明。格式如下：

```
{角色特征详细描述}。{视觉风格类型名}风格化造型：{从 reference 文件 string8_style_injection 字段提取的关键词}
```

示例（3DCartoon）：
```
...气质沉稳干练有安全感。3DCartoon风格化造型：soft rounded facial features柔和圆润五官，big expressive eyes大而有神眼睛，smooth porcelain skin光滑瓷肌，playful proportions俏皮卡通比例，adorable and wholesome aesthetic可爱健康美学
```

### 风格关键词成组使用规则

- 从 reference 文件提取的 string1/string2/string11/string12 关键词**必须整组注入**，不允许拆分或删减
- 保持模板原文的词汇关联性，不重新排列顺序
- 如需额外补充，追加在末尾而非插入中间

## 七视图 Prompt 模板

global 模式（Tier 1 选角 + Tier 2 定妆/新妆造）共用此模板。Prompt 必须严格使用下方模板，逐字替换占位符（string0~string12）。**禁止**自己编写新的 Prompt 格式，**禁止**改为单视图/单角度描述，**禁止**使用"角色参考图：XXX — 某视角"标题格式。

```
{string0}，
{string1}，8K中超清，极致细节，影视级质感，50mm f2.8镜头，浅景深，焦点精准，{string2}角色七视图设定图，七视图网格排版。
画面左半侧为角色半身正面照，50mm焦段拍摄，自然微笑表情，展示人物面部、{string3}、{string4}、{string5}细节；
画面右半侧上方三分之一区域为角色头部表情三连图，从左至右依次为：开心（灿烂笑容）、难过（悲伤神情）、愤怒（怒目而视），头部特写，表情生动自然，五官与半身照完全一致；
画面右半侧下方三分之二区域为角色全身三视图，并列展示全身正面、全身侧面、全身背面三个视图，三视图人物服装、发型、头饰完全一致，完整站立，全身入镜，比例协调，高端{string6}角色设定海报质感。
主体为一位{string7}，{string8}。
{string9}，
{string10}，
{string11}，
{string12}，
服装上没有任何文字、logos、标签或文字标识，no text，no logo.
```

## 群像专用 Prompt 模板

群像模式使用独立模板，不适用上述七视图模板。模板如下：

```
{string0}，
{string1}，8K中超清，极致细节，影视级质感，{string2}角色群像设定图，团队阵容展示。
画面呈现{群组-角色数量}位角色并排站立于纯{群组-背景色}背景前，全身入镜，从左至右依次为：{群组-角色列表及特征}。角色间保持合理间距，主次分明，{群组-C位描述}，角色比例协调，服装发饰风格统一，高端{string6}角色群像设定海报质感。
主体为{群组-整体定位描述}。
{string11}，
{string12}，
所有服装上没有任何文字、logos、标签或文字标识，no text，no logo.
```

## 参数说明

### 七视图参数

global 模式（Tier 1 选角 + Tier 2 定妆/新妆造）使用以下参数。Tier 1 与 Tier 2 对参数的取值来源有差异，见 `rules/global.md`。

| 参数 | 含义 | 说明 |
|------|------|------|
| string0 | 一致性引导词 | 由各模式自行定义（见 global/episode 规则） |
| string1 | 质感类型 | 由角色视觉风格决定，从「string1 质感类型选择表」中选择对应值 |
| string2 | 美学风格 | 如"东方古典仙侠美学"、"赛博朋克美学" |
| string3 | 头饰（简述） | 从角色设定「造型设计」当前妆造名下提取 |
| string4 | 妆容（简述） | 从角色设定「造型设计」当前妆造名下提取 |
| string5 | 服装（简述） | Tier 1 选角固定为"白色短袖T恤"；Tier 2 从「造型设计」当前妆造名下提取 |
| string6 | 剧集风格 | 如"森系仙侠"、"硬科幻" |
| string7 | 性别+年龄 | 如"年轻女性"、"45岁男性" |
| string8 | 角色特征 | 皮肤、五官、脸型、发型、胡须状态（有/无及类型）、身材、气质、性格等，≥80字。末尾追加风格化造型描述（从 reference 文件 `string8_style_injection` 字段提取） |
| string9 | 头饰详述 | ≥80字详细描述。从角色设定「造型设计」当前妆造名下扩展 |
| string10 | 服装详述 | ≥80字详细描述。推荐按结构化三段式编写：品类（如 oversized knitted sweaters, fluffy jackets, cropped tops, wide-leg jeans）+ 材质（wool, fleece, knit 等纹理面料）+ 色彩（显式指定色板，如 warm color palette with pastel and vibrant tones: orange, teal, purple, yellow），可选追加配件（backpack, sling bag, headphones, goggles）和同伴（cute animal companion on shoulder）。Tier 1 选角固定为"白色短袖T恤，简约干净，无图案无文字"；Tier 2 从「造型设计」当前妆造名下扩展 |
| string11 | 背景+光影 | 摄影棚氛围、光线方向、质感描述。必须使用中英双语并列格式，从 reference 文件 `string11` 章节提取。Tier 1 选角固定为"工业级中灰无影墙，光线柔和自然，无色光，均匀照明无阴影" |
| string12 | 整体质感 | 如"照片级真实质感"、"彩色铅笔画质感"。必须使用中英双语并列格式，从 reference 文件 `string12` 章节提取 |

> **Tier 1 选角固定项**：string5 固定为"白色短袖T恤"，string10 固定为"白色短袖T恤，简约干净，无图案无文字"，string11 固定为"工业级中灰无影墙，光线柔和自然，无色光，均匀照明无阴影"。镜头固定为 50mm f2.8，半身照表情为自然微笑，表情三连图为开心/难过/愤怒。这些固定项仅在 Tier 1 选角资产中生效（见 `rules/global.md` 步骤 3a），Agent 不可覆盖。Tier 2 定妆/新妆造的 string5/10/11 从「造型设计」和 reference 文件提取，不使用固定值。

### 群像专属参数

| 参数 | 含义 | 说明 |
|------|------|------|
| 群组-角色数量 | 群组成员总数 | 从群组设定文件读取 |
| 群组-背景色 | 纯色背景颜色 | 默认"浅灰色"，可由群组设定覆盖 |
| 群组-角色列表及特征 | 每位角色的排布顺序 + 关键特征 | 格式：左起依次为「角色A：蓝色连体工装，戴护目镜丨角色B：蓝色工装，戴降噪耳机」 |
| 群组-C位描述 | C位角色及其视觉突出描述 | 如"女主角居中，服装颜色略深于其他队员以突出主理人身份" |
| 群组-整体定位描述 | 群组的身份 / 角色定位 | 如"现代卫浴工厂操作员与街舞舞者融合的年轻团队" |

> **注意**：群像模式使用「群像专用 Prompt 模板」，不适用七视图模板。上述七视图参数表中的 string3~string12 在群像模式中不适用（由 `{群组-` 前缀占位符替代）。

## Schema 校验

调用 `scripts/validators.py` 的两个函数进行校验。

> **适用范围**：Schema 校验仅适用于 **global 模式**和 **group 模式**（生成 task JSON 的模式）。episode 模式产出妆造匹配清单 JSON，不调用 validators。

**任务级校验** — `validate_tasks(tasks, mode)`：

| 校验项 | 说明 |
|--------|------|
| 基础字段 | 每个 task 必须包含：prompt, imageSize, aspectRatio, filename, images |
| 类型检查 | imageSize **必须固定为** `1K`，aspectRatio **必须固定为** `16:9` |
| images/模式一致性 | 由 mode 参数决定：`global`（Tier 1 选角 + Tier 2 定妆）、`group`（群像） |
| prompt 完整性 | 无模板占位符（string0~string12），长度 ≥ 50 字符 |
| filename 合法性 | 必须以 .png 结尾 |

**顶层校验** — `validate_top_level(data)`：

| 校验项 | 说明 |
|--------|------|
| model | **必须固定为** `"gpt-image-2"` |
| output_path | 如果提供，必须为非空字符串 |
| tasks | 顶层必须包含 tasks 字段 |

校验通过标准：两个函数均返回空列表。
