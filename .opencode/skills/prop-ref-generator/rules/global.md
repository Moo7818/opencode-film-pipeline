# 全局基础参考流程

> 共享定义（Prompt 模板、参数表、校验规则）见 `rules/common.md`。

## 触发条件

- 阶段：全局视觉资产生成（global_character_tasks ~ global_scene_art）
- 输入：全局设定 + 道具设定 + 前期采样（道具/风格）

## 执行步骤

### 步骤 1：收集输入文件

| 文件 | 用途 |
|------|------|
| `project/{项目名}/全局依赖/全局设定.md` | 画风参考、色调色温、视觉语言标准 |
| `project/{项目名}/全局依赖/道具设定/道具设定.md` | 道具索引清单 |
| `project/{项目名}/全局依赖/道具设定/具体设定/{道具名}.md` | 各道具详细设定 |
| `project/{项目名}/前期采样/道具/{道具名}*.png` | 道具采样图（可选，决定是否作为参考图） |
| `project/{项目名}/前期采样/风格/*.png` | 风格参考图 |

### 步骤 2：确定道具清单并提取出现场合

从 `道具设定.md` 提取所有道具。每个道具 1 个 task，**task 数量 = 道具数量**。

对每个道具，读取 `具体设定/{道具名}.md` 的「基本信息」表，**必须**提取 `出现场合` 字段。该字段决定全局基准资产的文件名：

| 出现场合值 | 文件名中的取值 | 示例 |
|-----------|--------------|------|
| `全剧` | `全剧` | `{道具名}_全剧_基准.png` |
| `EP01` | `EP01` | `{道具名}_EP01_基准.png` |
| `EP01,EP13` | 取首集 `EP01` | `{道具名}_EP01_基准.png` |

> **出现场合缺失时**：若道具定义文件中未填写 `出现场合` 字段，Agent 应提示缺失并要求补充，**不得**自行猜测。此字段是防止道具资产被错误引用到不该出场的剧集中的核心标识。

### 步骤 3：模式判断

对每个道具，检查 `前期采样/道具/` 下是否存在以该道具名命名的图片文件：

| 模式 | 条件 | string0（一致性引导词） | 参考图 |
|------|------|------------------------|--------|
| **模式 A** | `前期采样/道具/{道具名}*.png` 存在 | **写实风格**: `"道具形态、结构、材质与质感严格遵循参考图片1-图片n"`; **非写实风格**: `"道具形态与结构严格遵循参考图片1-图片n"` | **道具采样图（必选，放images[0]）** + 风格参考图 |
| **模式 B** | `前期采样/道具/{道具名}*.png` 不存在 | `"视觉风格与材质质感严格参考参考图片"` | 仅风格参考图 |

> **模式 A 关键约束**：string0 必须使用"严格遵循"语气（不可弱化为"参考"），与 `images` 中传入的参考图形成双重一致性约束。
>
> **风格适配**：非写实风格下，string0 中的"材质与质感"字样需移除，因为材质质感由全局 style_desc 控制，不继承自参考图。

### 步骤 3A：分析参考图特征（仅模式 A）

在写入 prompt 前，**必须**对参考图进行视觉分析，提取实际可见的视觉特征。分析的核心目的不是"将设定转述为文字"，而是"描述参考图实际展示的内容"：

```
示例分析流程：
1. 文件名清单：[礼盒1.jpg, 礼盒2.jpg, 礼盒3.png, 礼盒4.jpg]
2. 覆盖视角：正面造型（礼盒1）、侧面细节（礼盒2）、顶部结构（礼盒3）、材质特写（礼盒4）
3. 核心视觉特征提取（从参考图中实际观察到的）：
   · 主色调：从参考图可见正红色中国红，色彩饱和度较高
   · 纹样：从参考图可见盒面龙凤纹样烫金工艺，金线反光强烈
   · 质感：参考图显示烤漆表面，反光均匀有镜面感
   · 光影：参考图中光源从左上45°打光，形成高反差硬光质感，底部暗部较深
   · 未覆盖视角：背面、整体厚度 → 基于现有视角合理推断
4. 将提取到的特征写入 string3~string8 和 string9，描述应**聚焦于"参考图中看到什么"而非"设定文件中写了什么"**
```

> **关键约束**：分析输出的描述必须来源于参考图的实际视觉内容。设定文件仅用于补充参考图未覆盖的视角和细节。

### 步骤 3B：提取视觉风格

在执行步骤 4 构建 prompt 之前，按 `rules/common.md` 中「视觉风格提取」章节的规则，从 `project/{项目名}/全局依赖/全局设定.md` 中提取视觉风格关键字，记为 `{style_desc}`。

> **无全局设定时**：从 `前期采样/风格/` 中的参考图文件名判断风格倾向，仍无法判断时使用默认值"超写实影视级画面"。

### 步骤 4：构建 Prompt

使用 `rules/common.md` 的 **Prompt 模板**和**参数说明**逐字替换占位符（string0~string12）。

- **string0**：按上方模式判断确定。**模式 A 必须使用**：
  - n=1：`"道具形态、结构、材质与质感严格遵循参考图片1"`
  - n≥2：`"道具形态、结构、材质与质感严格遵循参考图片1-图片{n}"`
  - 不可弱化措辞。**关键**：`n` = 仅道具采样图数量（排除末尾的风格参考图）。例如 3 张道具采样图 + 1 张风格参考图时写 `图片1-图片3`，不是图片1-图片4
- **string12（模式 A 必填）**：`"图片{n+1}为视觉风格参考，用于引导整体色调、光影氛围与画面质感，不约束道具形态与结构。"`，其中 n = 道具采样图数量

| 参数 | 提取来源 | 通用说明（模式 B，无采样图） | 模式 A（有采样参考图）的参考图优先约束 |
|------|---------|---------|----------------------------------|
| style_desc | 全局设定.md | 从全局设定提取的视觉风格描述，如"超写实影视级画面"。无全局设定时默认"超写实影视级画面" | 同通用 |
| string1 | 道具用途 + 时代特征 | 如"明代航海导航器具" | 同通用 |
| string2 | 固定值 | `"焦点精准、材质质感突出"` | 同通用 |
| string3 | 正面视角（上左1） | ≥50字，从"外观描述"提取主体造型/比例/主色 | **零文字描述**。仅写 `正面` |
| string4 | 背面视角（上左2） | ≥50字，从"外观描述"推断背面结构/特征 | **零文字描述**。仅写 `背面` |
| string5 | 侧面视角（上右2） | ≥50字，从"外观描述"推断侧面轮廓/厚度 | **零文字描述**。仅写 `侧面` |
| string6 | 顶部视角（上右1） | ≥50字，从"外观描述"推断顶部结构/平面布局 | **零文字描述**。仅写 `顶部` |
| string7 | 关键部位特写1（下左） | ≥50字，从"外观描述"+"特殊效果"提取 | **零文字描述**。仅写 `{部位名}` |
| string8 | 关键部位特写2（下右） | ≥50字，另一角度局部细节/材质/纹样 | 同 string7 |
| string9 | 光线与氛围 | ≥50字，从"使用场景"推断光线环境 | **零文字描述**。仅写 `光线与氛围严格遵循参考图` |
| string10 | 状态 + 环境 | ≥40字，从"外观"+"使用场景"提取 | 仅写 `道具状态与品相严格遵循参考图所示` |
| string11 | 与 style_desc 风格一致 | 与 style_desc 风格一致的质感描述，如"电影级道具概念图质感" | 同通用 |
| string12 | 风格参考声明 | 留空（模式B的string0已覆盖风格参考） | **必须**写入：`"图片{n+1}为视觉风格参考，用于引导整体色调、光影氛围与画面质感，不约束道具形态与结构。"`，n = 道具采样图数量 |

### 步骤 5：生成任务 JSON

```json
{
  "model": "gpt-image-2",
  "tasks": [
    {
      "prompt": "道具形态、结构、材质与质感严格遵循参考图片1-图片n，{style_desc}，{string1}，1K分辨率，极致细节，{string2}，上4下2六视图排版。\n上方画面：左起依次为……\n下方画面：左起依次为……\n光线与氛围严格遵循参考图，\n道具状态与品相严格遵循参考图所示，\n{string11}.\n{string12}",
      "imageSize": "1K",
      "aspectRatio": "16:9",
      "filename": "{道具名}_{出现场合}_基准.png",
      "images": [
        "project/{项目名}/前期采样/道具/{道具名}.png",
        "project/{项目名}/前期采样/风格/{风格文件}.png"
      ]
    }
  ],
  "output_path": "project/{项目名}/全局依赖/道具设定/道具参考图/"
}
```

**自检清单：**
- □ tasks 数量等于道具数量
- □ 每个道具的 `出现场合` 字段已从 `具体设定/{道具名}.md` 提取并注入 filename
- □ filename 格式为 `{道具名}_{出现场合}_基准.png`（出现场合取首集集号或`全剧`）
- □ 每个 task 的 prompt 包含"上4下2六视图排版"
- □ style_desc 已从全局设定中提取并注入 prompt，非"超写实电影级"等硬编码风格
- □ mode_A（道具采样图存在）：string0 使用"严格遵循"措辞，images[0~n-1] 为道具采样图，images[n] 为风格参考图
- □ mode_A string0：n=1 写"参考图片1"，n≥2 写"参考图片1-图片{n}"（排除风格参考图）
- □ mode_A string0 根据风格类型正确选择：写实用"形态、结构、材质与质感"，非写实用"形态与结构"
- □ mode_A string12：包含"视觉风格参考，用于引导整体色调、光影氛围与画面质感，不约束道具形态与结构"
- □ mode_B（道具采样图不存在）：images 已添加风格参考图
- □ 模式 A 已执行参考图分析，images 数组已列出所有参考图
- □ **模式 A 的方位视图描述（string3~string8）零描述——仅视角名称（正面/背面/侧面/顶部/部位名），不映射图片编号**

### 步骤 6：Schema 校验

1. `validate_top_level(data)` 校验顶层
2. `validate_tasks(tasks, "global")` 校验任务列表

### 步骤 7：输出完成提示

使用 `rules/common.md` 中的完成提示。

## 参考图上传顺序

### 模式 A（有道具采样图）

| 位置 | 内容 |
|------|------|
| images[0~n-1] | 道具采样图（`前期采样/道具/{道具名}*.png`） |
| images[n] | 风格参考图（`前期采样/风格/*.png`） |

> ⚠ **string0 计数规则**：`"严格遵循参考图片1-图片n"` 中的 `n` = **仅道具采样图数量**（images[0~n-1] 的元素个数），**不包括**风格参考图。n=1 时写 `"参考图片1"`（不要"图片1-图片1"），n≥2 时写 `"参考图片1-图片{n}"`。
>
> ⚠ **string12 风格声明**：**必须**写入 `"图片{n+1}为视觉风格参考，用于引导整体色调、光影氛围与画面质感，不约束道具形态与结构。"`，告知模型 images[n] 是风格参考而非道具参考。

### 模式 B（无道具采样图）

| 位置 | 内容 |
|------|------|
| images[0] | 风格参考图（`前期采样/风格/*.png`） |
