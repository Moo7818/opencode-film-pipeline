# 剧本处理规范

> **路径基准**：本规范中所有 `project/{项目名}/...` 路径均为**工作区根下**的相对路径（项目根 = 工作区根 `project/{项目名}/`，由 coordinator 创建）。**严禁**在 `.meta/`（含 `.meta/projects/`）下创建目录或写入业务文件——`.meta/` 是元数据区。

## 1. 原始剧本读取

### 1.1 文件路径定位

读取原始剧本时，按以下优先级定位文件：

1. 用户明确指定的路径
2. `project/{项目名}/原始剧本.md`
3. `project/{项目名}/原始剧本.txt`
4. 项目目录下任何以"剧本"或"script"命名的 Markdown 文件

### 1.2 格式识别

剧本可能包含以下格式标记：

- **场景标记**：`【场景】`、`[场景]`、`Scene:` 等
- **镜头标记**：`【镜头】`、`[镜头]`、`Shot:` 等
- **台词标记**：`【台词】`、角色名+括号或冒号（如 `郑和：`、`一岛（语气庄重）：`）
- **音效标记**：`【音效】`、`[音效]`、`Sound:` 等

### 1.3 内容解析规则

| 信息类型 | 识别方式 |
|---------|---------|
| 项目名称/标题 | 文件开头的第一行标题（`#`或加粗标题） |
| 核心主题 | 标题附近的主题声明行 |
| 角色清单 | 剧本开头的人物列表（`人物：` 或 `角色：` 开头行） |
| 场景清单 | 剧本开头的场景列表（`场景：` 开头行） |
| 基调说明 | 剧本开头的基调描述（`基调：` 开头行） |
| 道具清单 | 剧本开头的道具列表（`道具：` 开头行） |
| 场景内容 | 每个 `【场景】` 标记及其后续内容 |
| 镜头内容 | 每个 `【镜头】` 标记及其后续内容 |
| 台词内容 | 每个角色名后的台词文本 |
| 音效内容 | 每个 `【音效】` 标记及其后续内容 |

## 2. 内容提取方法论

### 提取范围总则

**只为核心项做设定**。提取前先判断对象是否值得单独创建设定文件：

| 类型 | 应提取（创建设定） | 不应提取（跳过） |
|------|-------------------|----------------|
| 角色 | 主角、关键配角、对剧情有推动作用的角色 | 过场角色、龙套、仅出现一次的群众 |
| 场景 | 剧本开头「场景：」清单中列出的主要场景、核心剧情场景 | 仅作为转场背景的过场场景 |
| 道具 | 核心角色专有道具、剧情关键道具、剧本开头「道具：」清单中列出的道具 | 场景背景中的装饰性道具、无关紧要的普通物品 |

### 2.1 角色提取

从剧本的以下位置提取角色信息：

1. **开头角色清单**：`人物：` 行给出基本信息（姓名、身份、服装等）
2. **场景描述**：角色出现时的场景描述包含外貌、动作习惯信息
3. **台词引导语**：如 `郑和（高声，面向船员）` 中的括号内容包含动作习惯和语气特征
4. **对话内容**：台词本身反映性格特征和语言习惯

### 2.2 场景提取

从剧本的以下位置提取场景信息：

1. **开头场景清单**：`场景：` 行给出场景名称和简要描述
2. **每个 `【场景】` 块**：包含场景的名称、时代、视觉描述
3. **基调描述**：`基调：` 行给出整体基调变化线索
4. **镜头描述**：`【镜头】` 内容包含光线、色彩、氛围的细节
5. **音效描述**：`【音效】` 内容补充场景氛围

#### 2.2.1 物理空间识别与场景合并（关键修正）

> **核心原则**：一个"场景" = 一个**独立的物理空间**（房间、建筑、户外地点），而非某个机位/焦段/区域。剧本中多组戏在同一物理空间的不同区域拍摄，不应拆分为多个独立场景。

**识别方法** — 对剧本中每个有 `场景设定：` 或 `【场景】` 标记的位置，判断它代表的是：

| 类别 | 定义 | 处理方式 |
|------|------|---------|
| **独立物理空间** | 与其他空间没有物理包含关系的完整空间 | 创建独立场景文件 |
| **子区域/机位** | 同一物理空间内的局部焦段、拍摄区域、镜头机位 | 合并到所属的父场景 |

**判断依据**（满足任意 2 条即判定为同一物理空间的子区域）：

1. **建筑元素共享** — 不同剧本组提到相同的标志性建筑/装修元素
   - 例如：《清悠居》"奢华婚礼现场"和"婚礼舞台中心"都提到"金龙浮雕背景墙"→ 同一空间
2. **空间包含关系** — 一个地点在语义上明显是另一个地点的组成部分
   - 例如："舞台中心"⊂"宴会厅"，"宾客席"⊂"宴会厅"，"舞台中央"⊂"宴会厅"
3. **无转场标记** — 两个剧本组之间没有明确的转场/切换标记（如空行+`---`、`【转场】`、"场景切换"等）
   - 《清悠居》第1~4组在同一个宴会厅内连续拍摄，第5组"场景设定：纯白/浅色调高端卧室"前有明显场景切换
4. **连续时间线** — 剧情在连续时间线上发生，没有时间跳跃
5. **同一基调氛围** — 共享相同的整体基调和色彩方案（如都是"金碧辉煌的婚礼氛围"）

**合并规则**：

当确认多个剧本组属于同一物理空间时，按以下方式合并为一个场景定义：

1. **场景名称**：使用概括最广的名称，合并表意为一个物理空间
   - 例如：`奢华婚礼现场` + `婚礼舞台中心` + `宾客席` + `舞台中央` → 合并为 `奢华婚礼宴会厅`
2. **视觉描述**：将所有子区域的视觉描述融合为一整段连贯的空间描述，明确标注各区域的空间位置关系
3. **关键元素**：合并所有子区域的关键元素列表，去重后统一列出
4. **光线/色彩**：汇总所有区域的光线色彩要求，注明不同区域/剧情阶段的变化
5. **氛围/基调**：合并为综合的空间氛围描述，覆盖所有子区域的情绪层次

**合并示例**（清悠居案例）：

| 原始拆分的"场景设定" | 判定 | 合并结果 |
|---------------------|------|---------|
| 奢华婚礼现场（第1组） | 宴会厅整体 | 合并为 **奢华婚礼宴会厅** |
| 宾客席（第2组） | 宴会厅的子区域 | → 写入"视觉描述"的宾客区段落 |
| 婚礼舞台中心（第3组） | 宴会厅的子区域 | → 写入"视觉描述"的舞台段落 |
| 舞台中央（第4组） | 宴会厅的子区域 | → 并入舞台段落 |
| 婚礼大厅（第8组） | 同宴会厅 | → 复用已定义的奢华婚礼宴会厅 |
| 纯白/浅色调高端卧室（第5~6组） | 独立物理空间 | 保留为独立场景 **高端卧室** |
| 直播间式背景（第7组） | 独立物理空间 | 保留为独立场景 **直播间背景** |

**自检清单**（输出前确认）：

- □ 每个场景文件对应一个**独立的物理空间**，没有将一个大厅拆成多个场景
- □ 剧本中多次出现的同一物理空间（如第1组和第8组都在宴会厅），没有重复创建设定文件
- □ 同一物理空间的子区域描述已合并到该空间场景文件的相应字段中

### 2.3 道具提取

从剧本的以下位置提取道具信息：

1. **开头道具清单**：`道具：` 行给出道具分类和清单
2. **场景描述**：道具在使用场景中被提及
3. **镜头描述**：特写镜头中出现的道具有视觉描述

### 2.4 分集剧本整理

将原始剧本转换为结构化分集剧本的规则：

1. **剧集编号**：如果只有一个剧本文件，编号从 `EP01` 开始
2. **分幕结构**：
   - 按原始剧本的幕/场景自然分组，保留剧本原有的场景结构
   - 每个 `【场景】` 标记为一个独立场景块
   - 同一幕下的场景归入同一幕，幕编号从 `第一幕` 开始按序递增
   - **不做**镜头级分解，不引入镜头编号
3. **台词处理**：
   - 原样保留，不做任何修改
   - 保留角色名和语气引导
   - 多行台词合并为一个台词块
4. **音效/配乐**：
   - 从剧本中提取所有音效描述
   - 标注在对应场景的末尾
   - 如果剧本描述了配乐情绪变化，补充配乐建议

## 3. 占位处理规则

当从剧本中无法提取某个字段时，按以下优先级处理：

1. **联网搜索填充**：如果该内容涉及历史真实人物/场景/道具，先用联网搜索到的权威信息填充
2. **合理推断**：无法搜索到精确信息但有足够时代背景线索的，基于历史背景合理推断
3. **使用占位符**：以上两者都不满足时，使用 `[待补充]` 并注明推断依据

具体规则：

| 情况 | 处理方式 |
|------|---------|
| 角色无明确外貌描述 | 历史人物 → 搜索历史画像/文献记载；虚构角色 → `[待补充 — 根据时代和身份推断]` |
| 角色无明确服装描述 | 历史人物 → 搜索该时代官服/民服规制（品级、颜色、形制）；虚构角色 → `[待补充 — 根据时代背景推断]` |
| 场景无明确光线描述 | 使用 `[待补充 — 根据氛围基调推断]` |
| 场景无明确色彩要求 | 使用 `[待补充 — 根据氛围基调推断]` |
| 道具外形不明确 | 历史道具 → 搜索历史形制、材质、工艺；虚构道具 → `[待补充 — 根据使用场景推断]` |

不允许凭空编造信息。如果无法推断且搜索不到参考，必须使用 `[待补充]` 并注明推断依据。

## 4. 历史内容识别与联网补充规则

### 4.1 适用范围

本规则适用于原始剧本中涉及的所有**真实历史内容**，包括但不限于：

| 类别 | 识别关键词/模式 | 示例 |
|------|----------------|------|
| 真实历史人物 | 姓名与正史人物匹配；明确提及历史官职/封号 | 郑和、明成祖、朱棣、三宝太监 |
| 真实历史事件 | 提及历史事件名称或明确年份 | 下西洋、永乐年间、宣德年间 |
| 真实历史地理 | 真实地名、国家、水域、关隘 | 龙江关、西洋、南京、太仓 |
| 真实官制/制度 | 提及真实官职、品级、机构 | 内官监太监、兵部尚书、司礼监 |
| 真实文化习俗 | 提及真实服饰、礼仪、建筑、器物 | 朝服、蟒袍、三山帽、玉带 |

### 4.2 搜索执行规范

**搜索时机**：读取原始剧本后、提取设定前，对识别出的每个历史项执行搜索。

**搜索维度**（每个历史项搜索以下维度）：

```
历史人物:
  ├─ 身份背景: "{人物名} 生平 官职"
  ├─ 服饰规制: "{人物名} 服饰 规制" 或 "{时代} {官品} 官服"
  ├─ 历史记载: "{人物名} 明史 列传" （如有必要）
  └─ 视觉参考: "{人物名} 画像" 或 "{人物名} 塑像"

历史场景（地理）:
  ├─ 地理位置: "{地名} 明代 位置" 或 "{地名} 历史沿革"
  ├─ 建筑特征: "{建筑名} 明代 形制" 或 "{地名} 明代 建筑"
  └─ 时代背景: "{事件} 明代 历史背景"

历史道具/器物:
  ├─ 形制特征: "{器物名} 明代 形制" 或 "{器物名} 工艺"
  └─ 用途规制: "{器物名} 用途 规制"
```

**搜索结果使用原则**：

1. **精确替代模糊**：搜索到的精确历史信息直接替代剧本中的笼统描述
   - 例如：剧本写"明朝官服" → 搜索发现郑和赐服蟒袍，产出写"四爪蟒袍（赐服），红色织金"
2. **多源交叉验证**：至少参考 2-3 个来源，确保信息一致性
3. **标注来源**：所有搜索到的信息，在设定文件的"参考来源"部分标注来源链接或出处

### 4.3 信息注入示例

以郑和为例，搜索前后的对比：

| 字段 | 仅从剧本提取 | 联网搜索后补充 |
|------|------------|---------------|
| 头冠 | 明朝官帽 | 嵌金三山帽（明代中官特制官帽，以漆纱制成，圆顶，帽后三山之势） |
| 袍服 | 明朝官服（朝服） | 赐服蟒袍（四爪蟒纹，红色为贵，织金工艺，非普通朝服） |
| 腰带 | 腰带 | 玲珑白玉带（明代公侯一品以上方可佩玉带，属逾制特许） |
| 靴履 | 官靴 | 文武皂朝靴（明代官员标准黑色朝靴） |
| 身份 | 明朝官员 | 内官监太监（正四品），后钦封三宝太监，内官之首 |

### 4.4 异常处理

| 情况 | 处理方式 |
|------|---------|
| 搜索无结果 | 保持 `[待补充]` 占位，备注"已尝试搜索但未找到权威参考" |
| 搜索结果矛盾 | 优先采信正史记载（《明史》等），次选学术论文/博物馆资料 |
| 搜索超时/失败 | 回退到 `[待补充]` 占位策略，不影响后续流程 |
| 部分信息有结果 | 已有的填充，不足的继续保留 `[待补充]` |

### 4.5 与原有流程的关系

```
读取剧本 → [新增]分析识别历史内容 → [新增]联网检索补充 → 提取角色设定（融合搜索信息） → 提取场景设定（融合搜索信息） → 提取道具设定（融合搜索信息） → 生成分集剧本
                              ↑                              ↑                            ↑                            ↑
                          仅触发涉及历史     角色服装/外貌字段优先填入搜索到的精确信息   场景视觉/关键元素字段优先填入       道具形制/材质字段优先填入
                          内容的项目                                                    搜索到的历史地理信息                搜索到的历史器物信息
```
