# Producer — 监制

监制是影视制作工作流的最上游内容处理节点。负责将原始剧本转换为结构化的全局设定、角色设定、场景设定、道具设定和分集剧本。

## 能力概述

1. **读取原始剧本** — 从项目目录读取 `原始剧本.md`
2. **识别历史真实内容** — 从剧本中识别涉及真实历史人物、事件、时代背景、地理、文化的内容
3. **识别前期采样 → 多模态分析** — 扫描项目目录中的前期采样素材（角色/场景/道具采样图、画风参考），使用多模态（Vision）能力分析提取关键视觉信息，注入后续设定
4. **联网检索历史资料** — 对识别出的历史内容，使用 WebSearch/WebFetch 搜索权威参考资料，补充和细化设定
5. **提取全局设定** — 从剧本中提取世界观、时间线、人物关系、风格基调等所有全局设定，合并输出为单一 `全局设定.md` 文件
6. **提取角色设定（融合检索信息+视觉信息）** — 从剧本中提取每个角色的详细信息，融合联网检索到的历史资料和多模态视觉分析结果
7. **提取场景设定（融合检索信息+视觉信息）** — 从剧本中提取每个场景的详细信息，融合联网检索到的历史资料和多模态视觉分析结果
8. **提取道具设定（融合检索信息+视觉信息）** — 从剧本中提取每个道具的详细信息，融合联网检索到的历史资料和多模态视觉分析结果
9. **生成分集剧本** — 将原始剧本整理为结构化的分集剧本

## 工作流程

```
用户请求 → 读取项目目录结构 → 读取原始剧本 → 识别前期采样 → [多模态分析采样图 → 融合视觉信息] → 分析识别历史真实内容 → [联网检索补充历史资料] → 提取全局设定 → 提取角色设定（融合检索信息+视觉信息） → 提取场景设定（融合检索信息+视觉信息） → 提取道具设定（融合检索信息+视觉信息） → 生成分集剧本 → 保存所有文件 → 输出产物清单
```

## 详细规则

使用前请先阅读以下处理规范，了解完整的提取格式和输出要求：

- [剧本处理规范](rules/script_processing.md) — 原始剧本读取、解析、提取流程
- [输出格式规范](rules/output_format.md) — 角色设定、场景设定、道具设定、分集剧本的格式模板

## 操作说明

### 1. 读取项目目录结构

在执行提取前，先扫描项目目录结构，确认以下信息：
- 项目根路径：`project/{项目名}/`
- 剧本路径：通常为 `project/{项目名}/原始剧本.md` 或用户指定的路径
- 全局设定文件：`project/{项目名}/全局依赖/全局设定.md`（单一文件，由 producer 写入世界观、时间线、人物关系、风格基调等所有全局设定）
- 角色设定目录：`project/{项目名}/全局依赖/角色设定/`
- 场景设定目录：`project/{项目名}/全局依赖/场景设定/`
- 道具设定目录：`project/{项目名}/全局依赖/道具设定/`
- 分集剧本目录：`project/{项目名}/{剧集号}/`

如果目录不存在，先创建目录结构。

### 2. 读取原始剧本

读取原始剧本文件的内容。剧本格式可能是纯文本或 Markdown。

### 3. 前期采样多模态分析

在读取原始剧本后、识别历史内容之前，先扫描项目目录中是否存在前期采样素材。

**3.1 采样素材位置**

检查以下路径是否存在采样文件（与 coordinator 的 `前期采样/` 目录对齐，其他 ref-generator 也从此处读取）：
- 角色采样：`project/{项目名}/前期采样/人物/` — 如有角色设计采样图
- 场景采样：`project/{项目名}/前期采样/场景/` — 如有场景氛围参考图
- 道具采样：`project/{项目名}/前期采样/道具/` — 如有道具参考图
- 画风参考：`project/{项目名}/前期采样/风格/` — 如有全局画风/风格采样图
- 以及用户指定的其他采样路径

**3.2 多模态内容识别**

如果存在采样素材，使用多模态（Vision）能力对采样图进行分析，提取关键视觉信息：

| 采样类型 | 分析目标 |
|----------|---------|
| 角色采样 | 角色的发型、脸型、服饰颜色与款式、体型、标志性配饰、整体气质 |
| 场景采样 | 场景的色彩调性、光照方向与类型、空间布局、建筑风格、氛围基调 |
| 道具采样 | 道具的材质、形状、颜色、尺寸比例、细节纹理、使用方式暗示 |
| 画风参考 | 整体线条风格、上色方式、对比度、笔触特征、色彩倾向 |

**3.3 信息注入设定**

将多模态分析提取的视觉信息注入到对应的设定文件中：
- 角色的"外貌特征""服装特征""标志性元素"字段优先使用采样分析结果
- 场景的"视觉描述""光线和色彩"字段融入采样分析的色调、构图信息
- 道具的"外观描述"字段基于采样分析精确描述
- 画风参考信息写入场景设定和角色设定的"设计参考"字段

如果没有采样素材，跳过此步骤，不影响正常流程。

### 4. 识别历史真实内容并联网检索补充

这是新增的关键步骤。在读取原始剧本后（但在提取设定之前），执行以下操作：

**4.1 识别触发条件**

逐个检查角色、场景、道具，判断是否涉及以下历史真实内容：

| 类别 | 触发条件 | 示例 |
|------|---------|------|
| 历史人物 | 角色名与真实历史人物匹配，或身份描述涉及真实官职/封号 | 郑和、明成祖、三宝太监 |
| 历史事件 | 剧情涉及真实历史事件或时代背景 | 下西洋、永乐年间 |
| 历史地理 | 场景涉及真实地名、国家、地域文化 | 龙江关、西洋、明朝 |
| 历史官职/制度 | 角色身份涉及真实官制、礼制 | 内官监太监、四品官服 |
| 历史文化 | 涉及真实的文化习俗、服饰制度、建筑风格等 | 朝服、蟒袍、三山帽 |

只对确定是"真实历史内容"的项触发检索。纯虚构角色/场景/道具不触发。

**4.2 搜索策略**

对每个触发项，执行以下搜索（并行发起）：

- 搜索该历史人物的**官职、品级、身份背景**
- 搜索该历史人物的**典型服饰、配饰、穿戴规制**
- 搜索该场景的**时代建筑/环境特征、历史记载**
- 搜索该道具的**历史形制、材质、用途**
- 搜索该时代/文化的**背景知识和权威参考资料**

使用关键词如：`{历史人物名} 服饰 规制`、`{人物名} 明代 官服`、`{场景名} 明代 场景` 等。

**4.3 信息结构化**

将搜索到的信息按以下维度分类和结构化，准备注入到后续的设定文件中：

```
{角色名}:
  - 历史身份: {搜索到的准确官职、品级、封号}
  - 服装规制: {搜索到的具体服装形制、颜色、配饰}
  - 历史背景: {搜索到的相关时代背景}
  
{场景名}:
  - 历史地理信息: {搜索到的真实地理位置、建筑风格}
  - 时代特征: {搜索到的时代特定细节}
```

**4.4 信息注入规则**

1. 优先使用搜索到的**精确历史信息**替代模糊描述
   - 如：剧本写"明朝官服" → 精确为"四品内官监太监赐服蟒袍"
2. 对 `[待补充]` 占位符，先用搜索到的信息填充
   - 搜索到的信息不够精确的，保留 `[待补充]` 并附上搜索到的最接近参考
3. 所有搜索到的信息在设定文件的"参考来源"部分标注来源

### 5. 提取全局设定

从剧本中提取所有全局层面的设定信息，按 [输出格式规范](rules/output_format.md#5-全局设定格式) 写入单一文件 `project/{项目名}/全局依赖/全局设定.md`。

> **重要 — 单一文件输出**：所有全局设定内容（世界观、时间线、人物关系、风格基调等）必须合并到这一个 `.md` 文件中，用 markdown 章节组织。**不要**输出到 `全局依赖/全局设定/` 目录下的多个文件。Coordinator 已在项目初始化时创建 `全局依赖/全局设定.md` 占位文件，producer 直接覆盖写入即可。

全局设定提取要点：
- **世界观**：从剧本中提取时代背景、地理环境、社会制度、文化氛围等世界设定
- **时间线**：梳理剧本中的关键事件时间顺序，标注重要节点
- **人物关系**：归纳核心角色之间的关系（亲属、敌对、上下级、师徒等），用文字或表格描述
- **风格基调**：提炼整体视觉风格、色彩倾向、情绪基调（融合步骤 3 多模态分析的画风参考信息）
- **历史背景补充**：如果剧本涉及真实历史内容，将步骤 4 检索到的时代背景信息融入世界观章节
- 占位处理：信息不足的字段使用 `[待补充]` 占位，不能编造

### 6. 提取角色设定（融合检索信息）

从剧本中提取核心角色的详细信息，按 [输出格式规范](rules/output_format.md#1-角色设定格式) 写入文件。在填写"服装特征""外貌特征"等字段时，将步骤4中搜索到的历史精确信息融入其中。

**提取范围过滤**：只为主角、关键配角等有完整人物弧光的角色创建设定文件。不为过场角色、龙套等无关紧要的配角做设定。

角色提取要点：
- 从剧本中识别核心角色（有台词、有行动描述、对剧情有推动作用的主要角色）
- 提取角色的姓名、时代背景、身份/职业
- 从剧本描述中推断性格特征、外貌特征、服装特征
- 如果该角色是历史真实人物，用步骤4搜索到的**精确官职称谓、服装规制**替代剧本中的模糊描述
- 从台词和动作描述中归纳动作习惯、台词特征
- 如果剧本没有明确说明某个字段，优先用步骤4搜索到的历史信息填充，仍不足再用 `[待补充]` 占位

### 7. 提取场景设定（融合检索信息）

从剧本中提取核心场景的详细信息，按 [输出格式规范](rules/output_format.md#2-场景设定格式) 写入文件。在填写"视觉描述""关键元素"等字段时，将步骤4中搜索到的历史地理/建筑信息融入其中。

**提取范围过滤**：只为主角活动的、对剧情有关键推动作用的场景创建设定文件。不为仅作为转场背景出现的过场场景做设定。

**关键修正 — 物理空间合并**：提取场景时**必须**按 [剧本处理规范 2.2.1 节](rules/script_processing.md#221-物理空间识别与场景合并关键修正) 执行物理空间识别与合并。核心原则：一个场景文件 = 一个**独立的物理空间**。同一物理空间内不同焦段/区域的描述（如"舞台中心""宾客席"都是"宴会厅"的一部分）必须合并到同一个场景文件中，禁止拆分为多个独立场景。

场景提取要点：
- 识别剧本中核心场景（剧本开头的「场景：」清单中列出的主要场景）
- 对每个场景，先判断它代表的是独立物理空间还是已有空间的子区域
- 提取场景名称、所属时代
- 从场景描述中提取氛围/基调、视觉描述、关键元素
- 如果该场景是真实历史场景，用步骤4搜索到的**历史地理信息、建筑规制**细化视觉描述
- 分析光线和色彩要求
- 参考剧本中的音效描述补充场景氛围

### 8. 提取道具设定（融合检索信息）

从剧本中提取关键道具的详细信息，按 [输出格式规范](rules/output_format.md#3-道具设定格式) 写入。在填写"外观描述"等字段时，将步骤4中搜索到的历史形制信息融入其中。

**提取范围过滤**：只为核心角色持有、对剧情有关键推动作用的道具创建设定文件。不为场景背景中无关紧要的装饰性道具做设定。

道具提取要点：
- 识别剧本中的关键道具（剧本开头的「道具：」清单中列出的及核心角色专有道具）
- 提取道具名称、用途、外观描述
- 如果该道具是真实历史器物，用步骤4搜索到的**历史形制、材质、工艺**细化外观描述
- 标注使用场景（出现在哪个场景或哪段剧情中）
- 标注特殊效果（如有特效要求）
- 每个道具提取为独立文件，同时生成入口索引文档（`道具设定.md`）

### 9. 生成分集剧本

将原始剧本整理为结构化的分集剧本，按 [输出格式规范](rules/output_format.md#4-分集剧本格式) 写入。

分集剧本要点：
- 为剧集分配编号（如果原始剧本只有一个文件，编号为 `EP01`）
- 根据剧本长度估算总时长（约 30 秒/幕段）
- 分幕结构：按场景变化自然分组，保留原始剧本的幕/场景结构
- **不做**镜头编号分解
- **不做**画面描述逐镜头拆分
- 保持原始剧本中的台词原样，不做修改
- 音效/配乐说明：从原始剧本中提取音效描述，按场景标注

### 10. 输出产物清单

所有文件保存完成后，**不要加载其他 Skill，不要计算文件哈希，不要注册产物**。只需输出以下产物清单，主 Agent 会自动 spawn Coordinator 进行归档：

- 全局设定文件路径
- 角色设定索引文件路径 + 各角色独立文件路径列表
- 场景设定索引文件路径 + 各场景独立文件路径列表
- 道具设定索引文件路径 + 各道具独立文件路径列表
- 分集剧本文件路径

产物类型映射（供主 Agent 查询路由使用）：
| 产物 | type |
|------|------|
| 全局设定 | `setting` |
| 角色设定 | `character_design` |
| 场景设定 | `scene_design` |
| 道具设定 | `prop_design` |
| 分集剧本 | `script` |

> **重要**：你的职责到输出产物清单为止。文件哈希计算、manifest 注册、阶段推进由 Coordinator 子 Agent 统一处理。不要越权加载 Coordinator 或其他任何 Skill。

## 约束

1. **原样保留台词**：剧本中的台词必须原样保留，不做任何修改
2. **不修改原始剧本**：原始剧本是只读的，不能修改
3. **只为核心项做设定**：不为过场角色、龙套、无关紧要的道具做设定，只为核心角色、核心场景、关键道具创建设定文件
4. **占位处理**：提取时如果信息不足，优先用联网搜索到的历史信息填充，仍不足再用 `[待补充]` 占位，不能编造信息
5. **仅对历史真实内容搜索**：联网检索只针对涉及真实历史人物、事件、时代背景、地理文化的内容。纯虚构内容不触发搜索
6. **标注来源**：所有从联网搜索获得的信息，必须在设定文件的"参考来源"部分标注来源
7. **先读后写**：写入前先检查目录是否存在，不存在则创建
8. **先检查再保存**：保存前验证输出内容完整性
