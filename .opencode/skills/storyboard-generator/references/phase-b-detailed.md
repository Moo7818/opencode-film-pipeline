# Phase B（详细模式）：分镜脚本 JSON 生成

> 当 `meta_query(scope=config)` 返回的 `config.storyboard_mode` 为 `"detailed"` 或未设置时执行此分支。Phase A 不变，产出 `分镜稿_临时.md` 供本阶段消费。

---

## B1：读取 Phase A 产出 + 原始分集剧本

Phase B 必须同时读取以下两份文件，**严禁只读其一**：

1. **分镜稿_临时.md**（Phase A 产出）：`{剧集号}/分镜/分镜稿_临时.md`
   - 场次戏剧地图（确定场级切分）
   - 逐场 shot flow（确定组级和镜头级推进逻辑）
   - 粗略缩略图任务（确定镜头景别、画面、cut 动机）
   - 台词时长校验结果（确定镜头时长分配）
    - 时空故事节点表 + 物理场归并表（A2 产出；**分场以物理场为准**，节点只服务节奏）

2. **分集剧本**（原始剧本）：`project/{项目名}/{剧集号}/剧本.md`
   - 逐字台词原文（确保台词与原始剧本逐字一致）
   - 画面内容与口播文案（确保剧情点不遗漏）
   - 幕/场景结构（交叉校验场级切分合理性）
   - **按行区间读取**：优先使用 Step 0 记录在分镜稿_临时.md 中的每场剧本行区间，用 `Read(offset, limit)` 只读当前场对应的行；无行区间表或剧本很短时整本读

> **为何要读两份**：Phase A 是创作性解读，会对台词做情绪标注、时长压缩、镜头化改写，但台词原文必须以分集剧本为准。Phase B 生成可执行分镜脚本时，**结构逻辑取自分镜稿，台词原文取自分集剧本**，二者交叉校验。只读分镜稿会导致台词漂移，只读分集剧本会丢失 Phase A 的镜头设计。

## 场的定义（物理空间，硬约束）

**一场 = 一个连续物理空间 + 连续故事时间。** 与 Phase A（A2-b）及 producer 场景设定对齐。

| 写入字段 | 要求 |
|---------|------|
| `场号` | 按物理场顺序递增 |
| `场名称` | 建议含空间+日夜，如「春生茶肆 日/内」 |
| `通用设定.场景名称` | **必须**对应该场唯一物理空间名（与场景参考图资产一致）；一场不得混写两个互不包含的地点 |

- 同空间多个戏剧节拍 → **一场多组**，禁止拆成多场
- 换地点或日→夜等时间断裂 → 新开场
- 下游分镜图按 `场号` 建串行参考帧链：同场不断链，异场可并行

## 场级连贯性规则

**规则 0：物理空间唯一** — 同一场内所有组的空间必须是同一物理地点；禁止一场内从茶肆切到包子铺再回来。

**规则 1：调度设计连贯** — 同一场内相邻组之间人物调度和空间走位形成连续空间叙事线。关键定位物位置一致，人物相对位置不突变，走动方向组间保持一致。

**规则 2：不越轴（180° 规则）** — 同一场内所有组摄影机轴线方向保持一致。如需越轴，中间必须插入中性镜头缓冲。

**规则 3：剧情与蒙太奇连贯** — 组间叙事推进自然流畅，情绪落点引导下一组的情绪起点。同场多故事节点时，节点边界落在**组**边界，不落在场边界。

## 硬约束

1. **台词时长**：每个含台词镜头的 hold ≥ 台词需时（Phase A 已按情绪语速模型计算并校验，Phase B 直接沿用分镜稿中的时长分配）
2. **组时长**：每组镜头时长之和 ≤ 15 秒
3. **组镜头数**：每组 ≤ 9 个镜头
4. **长镜头独占**：≥10 秒的镜头独占一组
5. **快切独立成组**：快切镜头组单独成组
6. **台词格式**：`台词` 字段格式为 `角色名：台词内容` 或 `旁白：内容`，由分镜脚本根据场景灵活选择，与原始剧本逐字一致。下游 video-director 会从 `台词` 字段提取角色名做音色匹配，无法提取角色名时按旁白处理
7. **字段完整**：每个镜头必须包含全部 17 个字段
8. **时间基准（组内相对时间）**：镜头列表中的 `开始/结束时间` 一律**以当前组为基准**计算——每组首镜必须 `0-X` 起始（如 `"0-3"`），组内镜头从 0 连续累加。**禁止**以整集（全片）或整场为基准计算时间（如第二组首镜写 `"8-10"`——那是它在该集中的绝对起点；同场第二组也不得承接场内累计时间）。下游 video-director 逐组独立消费，组间时间互不相关。合并脚本检测到首镜非 0 的组会整组平移归零并输出告警——这是兜底而非许可，仍应按 0 起始编写
9. **字数范围**：场景描述 20~40 字，站位/调度 25~50 字，人物心理活动 10~25 字，表演/微表情 15~30 字，光线 20~40 字，氛围 15~30 字
10. **纯中文输出**（除 f/2.8 等技术表达外）
11. **通用设定在场级统一定义**；`场景名称` 一场一物理空间
12. **场级连贯性**：遵守物理空间唯一、调度连贯、不越轴、剧情蒙太奇连贯
13. **音频规则**：仅允许对白和音效，禁止背景音乐
14. **禁止冗余描述**：去掉"仿佛""让观众感受到""传递出""营造出"等引导性修辞，描述像导演给摄影师的指令一样精炼
15. **表演/微表情必须包含眼神方向**：每个镜头的`表演/微表情`字段必须描述角色眼神看向何处（如：望向镜头、看向产品、与对手对视、视线跟随物体移动等），建立明确的视线关系
16. **妆造名标注**：当角色在某场戏中穿着非默认妆造时，在`场景描述`或`站位/调度`字段中标注妆造名，格式为 `[妆造:名]`。例如：`[妆造:战斗铠甲] 郑和立于旗舰船头`。默认妆造无需标注。该标注供下游角色参考图生成器匹配妆造衣橱使用
17. **禁止按戏剧节拍拆场**：同物理空间的多个节拍必须写在同一 `场号` 的多个 `组` 内

## 写入文件（场文件直写，每场一个独立 JSON）

基于 Phase A 分镜稿中的场次戏剧地图、shot flow、粗略缩略图任务、时空故事节点表，**并交叉对照分集剧本中的逐字台词与画面内容**，按上文的 JSON 格式、场级连贯性规则和硬约束逐场生成。

> **为什么不再用 Edit 追加单个大 JSON**：超长 newString 的 Edit 追加是脆弱写法——一次转义损坏即破坏整个交付文件，且损坏要到很晚才暴露。改为**每场 Write 一个独立小文件**：单场载荷小、每次写入都是完整合法 JSON、损坏半径仅一场、断点恢复零成本。

### 逐场写入流程

**核心思路**：每场 Write 一个 `场{N}.json` 到 `{剧集号}/分镜/场文件/` 目录。agent 上下文只持有当前正在生成的场，不持有已写入的场；**全程不使用 Edit 追加**。

**Step 0 — 建目录并写入 场1.json**：
`{剧集号}/分镜/场文件/场1.json`，内容为**仅含场1的单元素数组**（或直接写场1对象）：

```json
[
  {
    "场号": 1,
    "场名称": "...",
    ...17字段完整...
  }
]
```

**Step 1 — 逐场 Write**：每生成一场（场号 N），Write `场{N}.json`（同样为单元素数组）。文件名必须与场号一致，脚本按文件名数字排序合并。

**Step 2 — 重复 Step 1** 直到全部场写入完成。

**即时自检（可选但推荐）**：任一场写完后可立即校验该场，早发现格式问题：

```bash
.venv 解释器 ".opencode/skills/storyboard-generator/scripts/validators.py" --check "场{N}.json"
```

### 断点恢复

若会话中断后重新拉起：

1. **Read 分镜稿_临时.md**：获取完整场次列表（共 N 场）+ 每场的 shot flow + 连贯性约束
2. **LS `场文件/` 目录**：列出已有 `场{M}.json`，缺失的场号即续写点
3. **从缺失场继续 Write**：交叉对照分集剧本台词，按场级连贯性规则衔接已有场的末尾状态
4. 全部场文件就绪后进入合并拆分步骤

> **恢复判定**：目录不存在或为空 → 从场1开始；已有最大场号 < 总场数 → 从缺失场继续；全部场文件就绪 → 直接合并拆分。单个损坏的场文件只需重写该场，不影响其余场。

### 合并与拆分（一条命令）

**必选**：全部场文件就绪后，调用 `expand_scenes_to_groups.py` 一次性完成 **合并 → 逐文件校验 → 组时间归零 → 写出 `分镜脚本.json` → 拆分组文件**。下游 video-director 强依赖 `分组/组{N}.json`，此步骤不可跳过。

```bash
.venv解释器 ".opencode/skills/storyboard-generator/scripts/expand_scenes_to_groups.py" \
  --input "project/{项目名}/{剧集号}/分镜/场文件/" \
  --output-dir "project/{项目名}/{剧集号}/分镜/分组/"
```

- 合并产物默认写到输入目录上级的 `分镜脚本.json`（即 `{剧集号}/分镜/分镜脚本.json`），可用 `--output` 显式指定
- **逐文件校验**：任一场文件 JSON 损坏会当场指名报错（文件名 + 行列号）并退出，不带病前进
- **组时间归零**（兜底）：首镜非 0 起始的组整组平移归零；跨度与 `时长` 字段不一致时输出告警；`--no-normalize-time` 可关闭
- 末尾输出每场摘要（组数/镜数），会话无需回读文件核对

### 脚本执行守则（Windows/Unix 通用）

- **解释器探测（每会话一次）**：优先 `.venv/Scripts/python.exe`（Windows）→ `.venv/bin/python`（Unix）→ 裸 `python`。**禁止**使用 `python3` 或 `py`：Windows 上 `python3` 被 Microsoft Store 别名劫持，`py` 常未安装
- **禁止内联 `-c` 传中文**：需要脚本处理中文内容（路径/字段/文本）时，先 Write 临时 `.py` 文件（UTF-8）再执行——Windows GBK 控制台会把内联 `-c` 里的中文打烂
- 本技能所有脚本已内置 UTF-8 stdout 重配置，可直接在 GBK 控制台运行

## 自检清单

生成完成后确认：
- [ ] 格式为场→组→镜三级结构
- [ ] **每场对应唯一物理空间**；同空间多节拍为多组而非多场
- [ ] `通用设定.场景名称` 与场名称空间一致，一场不混地点
- [ ] 每个镜头包含全部 17 个字段
- [ ] 口播文案按节奏分配到各镜头的`台词`字段
- [ ] **台词与分集剧本逐字一致**（交叉校验，非仅依赖分镜稿）
- [ ] 画面描述具体可执行，不模糊
- [ ] 每个镜头的`表演/微表情`包含眼神方向与注视对象
- [ ] 遵守硬约束（时长、字数、组限制等）
- [ ] 每组首镜 `开始/结束时间` 从 0 起始，全部时间以**当前组**为基准（非整集、非整场累计）
- [ ] 每场已 Write 为独立 `场文件/场{N}.json`，合并命令输出无 ERROR/WARN
- [ ] 无背景音乐，无画面文字
- [ ] `分镜脚本.json` 场数 = 分镜稿场次戏剧地图的场数（无遗漏）
