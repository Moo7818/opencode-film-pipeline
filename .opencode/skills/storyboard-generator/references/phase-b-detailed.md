# Phase B（详细模式）：分镜脚本 JSON 生成

> 当 `project_config.json` 的 `storyboard_mode` 为 `"detailed"` 或未设置时执行此分支。Phase A 不变，产出 `分镜稿_临时.md` 供本阶段消费。

---

## B1：读取 Phase A 产出 + 原始分集剧本

Phase B 必须同时读取以下两份文件，**严禁只读其一**：

1. **分镜稿_临时.md**（Phase A 产出）：`{剧集号}/分镜/分镜稿_临时.md`
   - 场次戏剧地图（确定场级切分）
   - 逐场 shot flow（确定组级和镜头级推进逻辑）
   - 粗略缩略图任务（确定镜头景别、画面、cut 动机）
   - 台词时长校验结果（确定镜头时长分配）
   - 时空故事节点表（A2 产出，确定分场边界与时间流逝类型）

2. **分集剧本**（原始剧本）：`project/{项目名}/{剧集号}/剧本.md`
   - 逐字台词原文（确保台词与原始剧本逐字一致）
   - 画面内容与口播文案（确保剧情点不遗漏）
   - 幕/场景结构（交叉校验场级切分合理性）

> **为何要读两份**：Phase A 是创作性解读，会对台词做情绪标注、时长压缩、镜头化改写，但台词原文必须以分集剧本为准。Phase B 生成可执行分镜脚本时，**结构逻辑取自分镜稿，台词原文取自分集剧本**，二者交叉校验。只读分镜稿会导致台词漂移，只读分集剧本会丢失 Phase A 的镜头设计。

## 场级连贯性规则

**规则 1：调度设计连贯** — 同一场内相邻组之间人物调度和空间走位形成连续空间叙事线。关键定位物位置一致，人物相对位置不突变，走动方向组间保持一致。

**规则 2：不越轴（180° 规则）** — 同一场内所有组摄影机轴线方向保持一致。如需越轴，中间必须插入中性镜头缓冲。

**规则 3：剧情与蒙太奇连贯** — 组间叙事推进自然流畅，情绪落点引导下一组的情绪起点。

## 硬约束

1. **台词时长**：每个含台词镜头的 hold ≥ 台词需时（Phase A 已按情绪语速模型计算并校验，Phase B 直接沿用分镜稿中的时长分配）
2. **组时长**：每组镜头时长之和 ≤ 15 秒
3. **组镜头数**：每组 ≤ 9 个镜头
4. **长镜头独占**：≥10 秒的镜头独占一组
5. **快切独立成组**：快切镜头组单独成组
6. **台词格式**：`台词` 字段格式为 `角色名：台词内容` 或 `旁白：内容`，由分镜脚本根据场景灵活选择，与原始剧本逐字一致。下游 video-director 会从 `台词` 字段提取角色名做音色匹配，无法提取角色名时按旁白处理
7. **字段完整**：每个镜头必须包含全部 17 个字段
8. **时间连续**：同组内首镜从 0 开始
9. **字数范围**：场景描述 20~40 字，站位/调度 25~50 字，人物心理活动 10~25 字，表演/微表情 15~30 字，光线 20~40 字，氛围 15~30 字
10. **纯中文输出**（除 f/2.8 等技术表达外）
11. **通用设定在场级统一定义**
12. **场级连贯性**：遵守调度连贯、不越轴、剧情蒙太奇连贯三条规则
13. **音频规则**：仅允许对白和音效，禁止背景音乐
14. **禁止冗余描述**：去掉"仿佛""让观众感受到""传递出""营造出"等引导性修辞，描述像导演给摄影师的指令一样精炼
15. **表演/微表情必须包含眼神方向**：每个镜头的`表演/微表情`字段必须描述角色眼神看向何处（如：望向镜头、看向产品、与对手对视、视线跟随物体移动等），建立明确的视线关系
16. **妆造名标注**：当角色在某场戏中穿着非默认妆造时，在`场景描述`或`站位/调度`字段中标注妆造名，格式为 `[妆造:名]`。例如：`[妆造:战斗铠甲] 郑和立于旗舰船头`。默认妆造无需标注。该标注供下游角色参考图生成器匹配妆造衣橱使用

## 写入文件

基于 Phase A 分镜稿中的场次戏剧地图、shot flow、粗略缩略图任务、时空故事节点表，**并交叉对照分集剧本中的逐字台词与画面内容**，按上文的 JSON 格式、场级连贯性规则和硬约束生成。

直接写入 `{剧集号}/分镜/分镜脚本.json`

---

## 拆分为独立组文件

**必选：调用 expand_scenes_to_groups.py 拆分为独立组文件，供 video-director 逐组使用。** 下游 video-director 强依赖 `分组/组{N}.json`，此步骤不可跳过。

```bash
# Unix/macOS
.venv/bin/python3 ".opencode/skills/storyboard-generator/scripts/expand_scenes_to_groups.py" \
  --input "project/{项目名}/{剧集号}/分镜/分镜脚本.json" \
  --output-dir "project/{项目名}/{剧集号}/分镜/分组/"
```

```powershell
# Windows
.venv\Scripts\python.exe ".opencode\skills\storyboard-generator\scripts\expand_scenes_to_groups.py" `
  --input "project\{项目名}\{剧集号}\分镜\分镜脚本.json" `
  --output-dir "project\{项目名}\{剧集号}\分镜\分组\"
```

这一步是纯机械拆分：将场级 `通用设定` 注入到每个组中，生成独立组 JSON 文件。

## 自检清单

生成完成后确认：
- [ ] 格式为场→组→镜三级结构
- [ ] 每个镜头包含全部 17 个字段
- [ ] 口播文案按节奏分配到各镜头的`台词`字段
- [ ] **台词与分集剧本逐字一致**（交叉校验，非仅依赖分镜稿）
- [ ] 画面描述具体可执行，不模糊
- [ ] 每个镜头的`表演/微表情`包含眼神方向与注视对象
- [ ] 遵守硬约束（时长、字数、组限制等）
- [ ] 无背景音乐，无画面文字
