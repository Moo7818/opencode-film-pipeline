# Phase B（精简模式）：讲戏式分镜脚本

> 当 `project_config.json` 的 `storyboard_mode` 为 `"simplified"` 时执行此分支，替代详细模式的 Phase B。Phase A 不变，产出 `分镜稿_临时.md` 供本阶段消费。

---

## 核心原则

- **纯 Markdown 产出**：不生成任何 JSON 文件，分镜脚本仅为一份 `.md` 文档
- **讲戏式叙事**：像导演坐在监视器前给摄影师和演员讲戏，用自然流畅的口语描述每个镜头的画面、动作、情绪和技术参数，技术参数融入句中而非罗列
- **信息无损**：详细模式中 17 个字段的信息全部融入叙述文本，不丢信息，只是从结构化变为线性叙事
- **全局/场参数保留**：通用设定以结构化标签形式（风格质感、场景、光线、色调、氛围各占一行）写在场级头部
- **下游直接消费 .md**：拆分后的 `组{N}.md` 文件直接作为 video-director 的 prompt 内容

---

## Step 1：基于分镜稿 + 分集剧本生成分镜 Markdown

Phase B 必须同时读取以下两份文件，**严禁只读其一**：

1. **分镜稿_临时.md**（Phase A 产出）：`{剧集号}/分镜/分镜稿_临时.md` — 场次戏剧地图、shot flow、粗略缩略图任务、时空故事节点表，决定结构与镜头推进逻辑
2. **分集剧本**（原始剧本）：`project/{项目名}/{剧集号}/剧本.md` — 逐字台词原文、画面内容、口播文案，确保台词逐字一致、剧情点不遗漏

基于分镜稿中的场次戏剧地图、shot flow、粗略缩略图任务、时空故事节点表，**并交叉对照分集剧本中的逐字台词与画面内容**，生成**讲戏式 Markdown**。

**输出文件**：`{剧集号}/分镜/分镜脚本.md`

**格式规范**：

```markdown
# 分镜脚本

## 场1：{场名称}

{场叙事概述}。转场：{场转场}。总时长{场总时长}s。

通用设定：
风格质感：{风格质感}
场景：{场景名称}
光线：{光线基调}
色调：{色调调性}
氛围：{氛围基调}

---

### 组1（{组时长}s）·{组转场}

{组叙事概述}。

{第一镜的完整叙事段落，技术参数融入句中}

{第二镜的完整叙事段落，一个镜头一个自然段}

...

### 组2（{组时长}s）·{组转场}

{组叙事概述}。

{镜头叙事段落}
```

---

## 写作要求

1. **一段一镜**：每个镜头是一个完整的自然段，段落间通过镜头切换的自然逻辑衔接
2. **技术参数融入叙述**：景别、摄影机运动、角度、焦距景深等技术参数在描述到相关画面时自然带出，不单独罗列。例如："镜头从长江上空缓缓下降，极远景推至远景，深景深f/8将整片码头尽收眼底"
3. **台词融入叙述**：台词以角色说话的形式自然出现在叙事中，如：掌柜自言自语："上一秒还在改PPT，这一秒——我成掌柜了？" 无台词时不写
4. **音效融入叙述**：音效作为环境描写自然出现在段末，如："雨滴落入木盆的啪嗒声、手摸木地板的摩擦声在寂静中格外清晰"。无音效时不写
5. **后期特效融入叙述**：仅在有时提及，如："画面边缘水墨晕染，光柱中尘埃粒子浮动"
6. **禁止离散标签**：不使用 `**[镜N]**`、`台：`、`效：`、`景别：` 等前缀标签，不使用 `|` 分隔符
7. **表演必须含眼神方向**：在描述角色表演时自然带出眼神看向何处
8. **遵守详细模式全部硬约束**（时长、组限制、台词格式、场级连贯性、妆造名标注等，详见 `references/phase-b-detailed.md` 硬约束章节）

### 示例（单组单镜）

```markdown
### 组1（7s）·摇镜过渡

破茶馆室内全景建立，掌柜穿越醒来从地板起身环顾漏雨房梁。

破茶馆室内，晨光从破窗斜射入内，光柱中尘埃飘浮，房梁滴水落入木盆，水墨画山水背景。镜头从全景缓慢下降至掌柜面部，平拍缓降推镜。掌柜仰面躺在木地板上画面中央偏下，猛地睁眼，一只手摸地板——木头的。他坐起身，抬头看漏雨房梁，一滴水落在额头。大脑空白，试图理清穿越前后的记忆断层——睁眼瞬间瞳孔收缩，眉头紧皱，视线先看天花板又看自己双手，最后望向漏雨的房梁方向，嘴微张欲言又止。柔光从破窗斜入形成光柱，尘埃在光中飞舞，房梁滴水处有细小光斑闪烁，室内暗部呈灰褐色，破败冷清但带喜剧感。雨滴落入木盆的啪嗒声、手摸木地板的摩擦声在寂静中格外清晰。

掌柜自言自语："上一秒还在改PPT，这一秒——我成掌柜了？"
```

## Step 2：直接写入独立组文件

**不使用脚本拆分**。Agent 在 Step 1 完成 `分镜脚本.md` 后，已掌握全部组的完整内容，直接使用 Write 工具逐个写入 `组{N}.md` 文件到 `分组/` 目录。

> **为什么不使用脚本**：Markdown 是自由格式文本，LLM 产出的标题格式、分隔符、设定行写法存在自然差异，正则解析无法可靠覆盖。Agent 直接写入既准确又简单。

### 写入流程

1. 确保 `分组/` 目录存在（不存在则创建）
2. 按 `分镜脚本.md` 中的组顺序，逐个使用 Write 工具写入 `组{N}.md`
3. 每个文件从 `分镜脚本.md` 中提取对应组的内容，注入所属场的通用设定
4. 组号跨场连续编号（场1的组1-2 → 组1.md, 组2.md；场2的组1 → 组3.md）

### `组{N}.md` 文件格式（严格遵循）

```markdown
组时长：7s
转场：摇镜过渡
镜头数：1

通用设定：
风格质感：真人实拍电影级质感，唐代市井考据+适度写意，胶片感暖茶色基底
场景：春生茶肆（破店阶段）
光线：阴雨漫射光自破窗左上方斜射，光柱内尘埃浮动，茶炉暖光3200K补人物主光
色调：低饱和度灰褐主调，破败冷清中埋暖色希望，与赵胖红铺暖红形成冷暖冲突
氛围：卑微起点中藏戏谑，冷清里酝酿觉醒

破店全景坠落感铺场，掌柜仰躺醒来接受穿越事实。

春生茶肆室内大全景，雨自漏雨房梁一滴一滴落入右下木盆...
```

### 文件头字段说明

| 行 | 字段 | 格式 | 说明 |
|----|------|------|------|
| 第1行 | `组时长` | `组时长：Ns` | N为4-15的整数，用于 video-director 的 `--set duration` |
| 第2行 | `转场` | `转场：{转场方式}` | 如 切、摇镜过渡、推镜 |
| 第3行 | `镜头数` | `镜头数：N` | 该组包含的镜头数量 |
| 第5行 | `通用设定` | `通用设定：` | 标记行，下方为结构化字段 |
| 第6-10行 | 设定字段 | `{字段名}：{值}` | 五个维度各占一行：风格质感、场景、光线、色调、氛围 |
| 第12行起 | 组内容 | 组叙事概述 + 分镜段落 | 一段一镜，第一段为组叙事概述 |

### 镜头数计算

Agent 自行计算每个组的镜头数：组内容中**排除组叙事概述（第一段）和纯台词行**后的段落数即为镜头数。纯台词行指 `角色名："台词"` 或 `旁白：台词` 格式的短段落。

> **下游兼容**：video-director 读取 `组{N}.md` 全文作为 prompt。`组时长` 从文件首行 `组时长：Ns` 提取，`镜头数` 从 `镜头数：N` 行提取。无需 JSON 解析，叙事文本直接作为视频生成提示词。
